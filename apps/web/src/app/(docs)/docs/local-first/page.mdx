# Get started with local-first

This guide will help you get started with the Evolu local-first platform.

<Announcement>
  Upgrading from Evolu 7? Evolu 8 uses a different local storage format and does
  not migrate existing Evolu 7 databases yet. Automatic migration is planned.
  Until then, existing Evolu 7 data is preserved but is not shown in Evolu 8.
</Announcement>

<Note>
  Requirements: TypeScript 7 or newer with `exactOptionalPropertyTypes` enabled.
  Evolu supports the current major version of each tool it works with, such as
  Vite, Next.js, React, Svelte, Vue, Expo, React Native, Electron and Node.js,
  as its [examples](https://github.com/evoluhq/evolu/tree/main/examples) use
  them. Older versions may work, but aren't supported.
</Note>

## Updating

The local-first APIs aren't stable yet, so incompatible changes to them ship as
patch releases, with migration notes in the [release
notes](https://github.com/evoluhq/evolu/releases). Those changes are to the code
you write. An update keeps the data your deployed app stored on users' devices,
and when Evolu changes how it stores data, the updated app migrates existing
databases when it opens them. Read the release notes before you update, and
update the Evolu packages together, because a release of one can need the same
release of the others.

## Define schema

First, define your app database schema—tables, columns, and types.

Evolu uses [Type](/docs/api-reference/common/Type) for data modeling. Instead of plain JS types like string or number, we recommend using branded types to enforce domain rules. You can also define columns with any library that implements [Standard Schema](/docs/schema#standard-schema), such as Zod, Valibot, or ArkType.

```ts
import {
  id,
  NonEmptyTrimmedString100,
  nullOr,
  SqliteBoolean,
} from "@evolu/common";
// ---cut-start---
import { assertErr, assertType, createQueryBuilder } from "@evolu/common";
// ---cut-end---

// Primary keys are branded types, preventing accidental use of IDs across
// different tables (e.g., a TodoId can't be used where a UserId is expected).
const TodoId = id("Todo");
type TodoId = typeof TodoId.Output;

// Schema defines the database structure and mutation/query types.
// Validate untrusted input before insert/update/upsert.
const Schema = {
  todo: {
    id: TodoId,
    // Branded type ensuring titles are non-empty and ≤100 chars.
    title: NonEmptyTrimmedString100,
    // SQLite doesn't support the boolean type; it uses 0 and 1 instead.
    isCompleted: nullOr(SqliteBoolean),
  },
};
// ---cut-start---

const allTodos = createQueryBuilder(Schema)((db) =>
  db.selectFrom("todo").select(["id", "title", "isCompleted"]),
);
assertType<
  typeof allTodos.Row,
  {
    id: TodoId;
    title: NonEmptyTrimmedString100 | null;
    isCompleted: SqliteBoolean | null;
  }
>();
assertErr(Schema.todo.title.fromUnknown(""));
// ---cut-end---
```

<Note>
  Evolu automatically adds [system
  columns](/docs/api-reference/common/local-first/Schema/variables/SystemColumns-1):
  `createdAt`, `updatedAt`, `isDeleted`, and `ownerId`.
</Note>

## Create Evolu

After defining the schema, create Evolu for your environment. Evolu is multitenant: an app can have several accounts, called AppOwners, on one device, such as a personal one and a work one. `createEvoluApp` creates them, keeps them on the device, and opens one:

```ts
import {
  AppName,
  createEvoluApp,
  NonEmptyTrimmedString100,
} from "@evolu/common";
import { createEvoluDeps, createRun } from "@evolu/web";
// ---cut-start---
import {
  assertEqual,
  assertNotNull,
  createQueryBuilder,
  id,
} from "@evolu/common";

const Schema = { todo: { id: id("Todo"), title: NonEmptyTrimmedString100 } };
// ---cut-end---

const run = createRun(createEvoluDeps());
const app = await run.orThrow(
  createEvoluApp(Schema, {
    appName: AppName.orThrow("your-app-name"),
    auth: { type: "InstantStart" },
    createFirstAppOwner: true,
  }),
);

// The open AppOwner, with its Evolu instance.
const current = app.current.get();
if (current) {
  const evolu = await current.evolu;
  evolu.insert("todo", { title: NonEmptyTrimmedString100.orThrow("Buy milk") });
}
// ---cut-start---
assertNotNull(current);
const evolu = await current.evolu;
const titles = createQueryBuilder(Schema)((db) =>
  db.selectFrom("todo").select("title"),
);
assertEqual(await evolu.loadQuery(titles), [{ title: "Buy milk" }]);
await app[Symbol.asyncDispose]();
// ---cut-end---
```

The example sets two options that decide how the app starts: `auth` and `createFirstAppOwner`.

### Auth

Evolu encrypts not only the data an app syncs but also the data it keeps on the device, because malware can read a browser's or an app's storage. The device database, which keeps the AppOwners' secrets, needs a key such malware can't read. `auth` decides where that key comes from:

- `DeviceSecret` keeps it in secure storage malware can't read. On React Native, [`loadDeviceSecret`](/docs/api-reference/react-native/functions/loadDeviceSecret) keeps it in the iOS Keychain or the Android Keystore, with no prompt. A browser has no such storage, so on the web the only safe place is a passkey, which the user confirms on every start. [`createPasskeyAuth`](/docs/api-reference/web/functions/createPasskeyAuth) unlocks the secret with one, as the [passkey playground](/playgrounds/full/passkey) shows.
- `InstantStart` is for apps whose users won't keep anything sensitive in them, such as one made for fun, where a passkey prompt on every start only annoys users who don't see why it's needed. It needs no prompt, but its key is public, so it doesn't protect against malware that can read the app's storage.

[Privacy](/docs/privacy#encryption-on-the-device) explains what each protects.

### createFirstAppOwner

For some apps, mobile ones especially, it makes sense to create the user's account when they first open the app and open it again at every later start. Onboarding is simpler, and because the account is local, it costs nothing. A user who already has an account can restore it from a menu, or the app can ask on the first start, "Already use the app? Restore your account." The empty account can then be removed.

`createFirstAppOwner: true` does this. Evolu provides it because on the web, creating exactly one account is harder than it looks: the app can run in several tabs at once, and a check in app code, such as in localStorage or IndexedDB, can race and create two AppOwners. Evolu creates the first AppOwner when the device database is created, so there's always exactly one.

### Accounts

`app.appOwners` lists the AppOwners on the device, and `app.open` opens one as `app.current`. `app.add` adds a new AppOwner, or restores one from its mnemonic, and opens it. To restore one, validate what the user typed with `Mnemonic`, convert it with `mnemonicToOwnerSecret`, and pass the secret to `app.add`. [EvoluApp](/docs/api-reference/common/local-first/Evolu/interfaces/EvoluApp) describes each method, and the [examples](/docs/examples) show how full apps manage accounts.

A restored AppOwner syncs its data back from the relays in `transports`, except the rows of local-only tables, whose names start with `_`, because they never sync.

### React

In React, `EvoluAppProvider` from `createEvoluBinding` takes the app's promise, created once at module scope, such as `appPromise` from `run.orThrow(createEvoluApp(…))`, and provides the open AppOwner's instance, so `useEvolu` and the query hooks read its data. It renders under a Suspense boundary while the app opens, and renders `withoutAppOwner` while no AppOwner is open, such as after the user removed the last one:

```tsx {{ title: 'React' }}
import { createEvoluBinding } from "@evolu/react";
import { Suspense, type FC } from "react";
// ---cut-start---
import {
  AppName,
  assertTrue,
  createEvoluApp,
  id,
  NonEmptyTrimmedString100,
} from "@evolu/common";
import { createEvoluDeps } from "@evolu/react-web";
import { createRun } from "@evolu/web";
import { prerender } from "react-dom/static";

const Schema = { todo: { id: id("Todo"), title: NonEmptyTrimmedString100 } };
const run = createRun(createEvoluDeps());
const appPromise = run.orThrow(
  createEvoluApp(Schema, {
    appName: AppName.orThrow("your-app-name"),
    auth: { type: "InstantStart" },
    createFirstAppOwner: true,
  }),
);

const Todos: FC = () => <p>Todos</p>;
const CreateOrRestore: FC = () => <p>Create or restore an account</p>;
// ---cut-end---

const { EvoluAppProvider, useEvolu, useQuery } =
  createEvoluBinding<typeof Schema>();

export const App: FC = () => (
  <Suspense fallback={<p>Opening…</p>}>
    <EvoluAppProvider value={appPromise} withoutAppOwner={<CreateOrRestore />}>
      <Todos />
    </EvoluAppProvider>
  </Suspense>
);
// ---cut-start---

const { prelude } = await prerender(<App />);
assertTrue((await new Response(prelude).text()).includes("Todos"));
assertTrue(typeof useEvolu === "function" && typeof useQuery === "function");
await (await appPromise)[Symbol.asyncDispose]();
// ---cut-end---
```

In Vue, [EvoluAppProvider](/docs/api-reference/vue/variables/EvoluAppProvider) does the same, with composables typed by [createEvoluBinding](/docs/api-reference/vue/functions/createEvoluBinding), and in Svelte, [evoluAppState](/docs/api-reference/svelte/functions/evoluAppState) follows the open AppOwner and its instance.

### Relays

Without `transports`, Evolu syncs through `free.evoluhq.com`, a [testing relay](/docs/relay#hosting-evolu-relay) whose data may be deleted. Set your own relays before release, or pass `transports: []` to sync nothing.

### Supply your own owner

If an app's AppOwners come from outside Evolu, such as from a hardware wallet in an app like Trezor Suite, the app manages them itself and creates an Evolu instance with [`createEvolu`](/docs/api-reference/common/local-first/Evolu/functions/createEvolu) and the AppOwner as its `appOwner`:

```ts
import { AppName, createEvolu } from "@evolu/common";
import { createEvoluDeps, createRun } from "@evolu/web";
// ---cut-start---
import {
  assertSame,
  id,
  NonEmptyTrimmedString100,
  nullOr,
  SqliteBoolean,
  testAppOwner,
} from "@evolu/common";

const Schema = {
  todo: {
    id: id("Todo"),
    title: NonEmptyTrimmedString100,
    isCompleted: nullOr(SqliteBoolean),
  },
};
const appOwner = testAppOwner;
// ---cut-end---

const run = createRun(createEvoluDeps());
const evolu = await run.ok(
  createEvolu(Schema, {
    appName: AppName.orThrow("your-app-name"),
    appOwner,
  }),
);
// ---cut-start---

assertSame(evolu.appOwner, appOwner);
// ---cut-end---
```

## Handle errors

Evolu reports problems that stop the app from working, such as local data that needs a newer version of the app or an unexpected failure, in `run.deps.evoluError`, a store shared by all Evolu instances created from the same deps. Show it, or such a failure goes unnoticed. Render it outside the Suspense boundary that waits for Evolu, because the queries of a database that can't open stay pending:

```tsx
import { constNull } from "@evolu/common";
import { useSyncExternalStore, type FC } from "react";
// ---cut-start---
import { assertEqual } from "@evolu/common";
import { createEvoluDeps } from "@evolu/react-web";
import { createRun } from "@evolu/web";
import { prerender } from "react-dom/static";

const run = createRun(createEvoluDeps());
// ---cut-end---

export const EvoluErrorAlert: FC = () => {
  const error = useSyncExternalStore(
    run.deps.evoluError.subscribe,
    run.deps.evoluError.get,
    constNull,
  );
  if (!error) return null;
  return <p role="alert">Evolu error: {error.type}</p>;
};
// ---cut-start---

const { prelude } = await prerender(<EvoluErrorAlert />);
assertEqual(await new Response(prelude).text(), "");
// ---cut-end---
```

Vue follows the store with `useStore`, Svelte with `storeState`, and other frameworks subscribe to it the same way. [EvoluError](/docs/api-reference/common/local-first/Evolu/type-aliases/EvoluError) lists each error and what to ask the user. Each one blocks the app: after an `UnknownError`, for example, Evolu is in an unknown state, so ask the user to close all the app's tabs, or on React Native to restart the app. A problem syncing through a relay is not an `EvoluError`; the owner's [sync status](#sync-status) shows it.

Two cases can stop the app as it starts. While another build of the app, running in another tab, keeps the database, the app waits, and `evoluError` shown outside the Suspense boundary tells the user. When the device database is refused, `createEvoluApp` rejects, so put an error boundary of your own around the Suspense boundary.

`StartupErrorBoundary` below is an [error boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary) of the app's own, which catches `createEvoluApp`'s rejection and shows the failure instead of React unmounting the page:

```tsx
import { Component, Suspense, type FC, type ReactNode } from "react";
// ---cut-start---
import {
  AppName,
  assertTrue,
  constNull,
  createEvoluApp,
  id,
  NonEmptyTrimmedString100,
} from "@evolu/common";
import { createEvoluBinding } from "@evolu/react";
import { createEvoluDeps } from "@evolu/react-web";
import { createRun } from "@evolu/web";
import { useSyncExternalStore } from "react";
import { prerender } from "react-dom/static";

const Schema = { todo: { id: id("Todo"), title: NonEmptyTrimmedString100 } };
const run = createRun(createEvoluDeps());
const appPromise = run.orThrow(
  createEvoluApp(Schema, {
    appName: AppName.orThrow("your-app-name"),
    auth: { type: "InstantStart" },
    createFirstAppOwner: true,
  }),
);
const { EvoluAppProvider } = createEvoluBinding<typeof Schema>();

const EvoluErrorAlert: FC = () => {
  const error = useSyncExternalStore(
    run.deps.evoluError.subscribe,
    run.deps.evoluError.get,
    constNull,
  );
  if (!error) return null;
  return <p role="alert">Evolu error: {error.type}</p>;
};
const Todos: FC = () => <p>Todos</p>;
const CreateOrRestore: FC = () => <p>Create or restore an account</p>;
// ---cut-end---

class StartupErrorBoundary extends Component<
  { children: ReactNode },
  { failed: boolean }
> {
  override state = { failed: false };

  static getDerivedStateFromError(): { failed: boolean } {
    return { failed: true };
  }

  override render(): ReactNode {
    if (!this.state.failed) return this.props.children;
    return <p>The app couldn&apos;t start.</p>;
  }
}

export const App: FC = () => (
  <>
    <EvoluErrorAlert />
    <StartupErrorBoundary>
      <Suspense fallback={<p>Opening…</p>}>
        <EvoluAppProvider
          value={appPromise}
          withoutAppOwner={<CreateOrRestore />}
        >
          <Todos />
        </EvoluAppProvider>
      </Suspense>
    </StartupErrorBoundary>
  </>
);
// ---cut-start---

const { prelude } = await prerender(<App />);
assertTrue((await new Response(prelude).text()).includes("Todos"));
await (await appPromise)[Symbol.asyncDispose]();
// ---cut-end---
```

## Sync status

Evolu stores changes in the local database before they sync, so sync needs no UI while it works. Show the owner's sync status once, such as below the header, as one quiet line that appears only when no relay can be reached or a relay fails. React and Vue have `useOwnerSyncStatus` and Svelte has `ownerSyncStatusState`, while other frameworks subscribe to `run.deps.syncState` and pass its value, the database's name, and the owner's ID to [syncStateToOwnerSyncStatus](/docs/api-reference/common/local-first/Shared/functions/syncStateToOwnerSyncStatus), and [OwnerSyncStatus](/docs/api-reference/common/local-first/Shared/type-aliases/OwnerSyncStatus) describes each status and what to show for it.

## Mutate data

The examples below use `evolu`, the open AppOwner's instance.

<SinglePlatformCodeGroup>

```tsx {{ title: 'React' }}
import { sqliteFalse, sqliteTrue } from "@evolu/common";

import {
  AppName,
  assertEqual,
  createEvolu,
  createQueryBuilder,
  id,
  NonEmptyTrimmedString100,
  nullOr,
  SqliteBoolean,
  testAppOwner,

  todo: {
    id: id("Todo"),

    isCompleted: nullOr(SqliteBoolean),
  },
};
const run = createRun(createEvoluDeps());

  // ---cut-start---
  return null;
};

renderToString(
  <EvoluContext value={evolu}>
```

## Query data

Evolu uses type-safe TypeScript SQL query builder [Kysely](https://github.com/koskimas/kysely), so autocompletion works out-of-the-box.

Let's start with a simple `Query`.


In React, `useQuery` suspends until its query loads, so render it inside `Suspense`. To load several queries at once, without a waterfall of suspensions, use `useQueries`. A query SQLite fails, for example one with a syntax error in a raw SQL fragment, throws to the nearest error boundary, while other queries and mutations keep working. In Vue, an async setup under `Suspense` awaits `waitForRows` with the rows its query composables returned, and a failure reaches `onErrorCaptured`. In Svelte, `{#await}` awaits `loaded` of `queryState`.

Local queries are typically fast, especially with [indexes](/docs/indexes), so preloading is rarely needed. To start loading before a component renders, call `evolu.loadQuery`; `useQuery` reuses that load unless a mutation or sync drops it first.

Changes from other devices can arrive in any order, as [Sync](/docs/sync) explains, so a row can be incomplete and a related row can be missing for a while. [Queries](/docs/queries) shows how to write queries that handle that, and how to join and nest related rows.

## Delete data

To delete a row, set `isDeleted` to `sqliteTrue` (1). Synced tables use **soft deletes**. Tables prefixed with `_` delete the row permanently and have no sync history. In the examples below, `todoId` is the ID of the row to delete.

```ts {{ title: 'Vanilla JS' }}
const evolu = await run.ok(
  createEvolu(Schema, {
    appName: AppName.orThrow("LocalFirstDeleteVanilla"),
    appOwner: testAppOwner,
  }),
);
const { id: todoId } = evolu.insert("todo", {
  title: NonEmptyTrimmedString100.orThrow("New Todo"),
});
// ---cut-end---
// Mark a todo as deleted
evolu.update("todo", { id: todoId, isDeleted: sqliteTrue });
// ---cut-start---

const todoById = createQueryBuilder(Schema)((db) =>
  db.selectFrom("todo").select("isDeleted").where("id", "=", todoId),
```

When querying, filter out deleted rows:

```ts
// ---cut-start---
import {
  AppName,
  assertEqual,
  createEvolu,
  createQueryBuilder,
  id,
  NonEmptyTrimmedString100,
  nullOr,
  SqliteBoolean,
  sqliteTrue,
  testAppOwner,
} from "@evolu/common";
import { createEvoluDeps, createRun } from "@evolu/web";

const Schema = {
  todo: {
    id: id("Todo"),
    title: NonEmptyTrimmedString100,
    isCompleted: nullOr(SqliteBoolean),
  },
};
const createQuery = createQueryBuilder(Schema);
// ---cut-end---
const activeTodos = createQuery((db) =>
  db
    .selectFrom("todo")
    .selectAll()
    // Filter out deleted rows
    .where("isDeleted", "is not", sqliteTrue)
    .orderBy("createdAt"),
);
// ---cut-start---

const run = createRun(createEvoluDeps());
const evolu = await run.ok(
  createEvolu(Schema, {
    appName: AppName.orThrow("LocalFirstActiveTodos"),
    appOwner: testAppOwner,
  }),
);
const title = NonEmptyTrimmedString100.orThrow("New Todo");
const { id: activeTodoId } = evolu.insert("todo", { title });
const { id: deletedTodoId } = evolu.insert("todo", { title });
evolu.update("todo", { id: deletedTodoId, isDeleted: sqliteTrue });
const todos = await evolu.loadQuery(activeTodos);
assertEqual(
  todos.map((todo) => todo.id),
  [activeTodoId],
);
// ---cut-end---
```

<Warn>
  Synced tables retain deleted data to support merging across devices and time
  travel. This is essential for local-first systems where devices sync
  asynchronously. See [Time Travel](/docs/time-travel) to learn how to recover
  deleted data.
</Warn>

## Protect data

Evolu encrypts the data an app syncs and the data it keeps on the device, as [Privacy](/docs/privacy) explains. An AppOwner's mnemonic restores it on another device, and whoever has it can read and change all of the AppOwner's data, so let the user back it up and show it only to them, such as in a recovery UI that shows `evolu.appOwner.mnemonic`.

## Purge data

[`evolu.deleteDatabase()`](/docs/api-reference/common/local-first/Evolu/interfaces/Evolu#deletedatabase) deletes the instance's local database on this device, and [`evolu.deleteOwner(owner)`](/docs/api-reference/common/local-first/Evolu/interfaces/Evolu#deleteowner) deletes the rows of a shard or shared owner from it and stops syncing the owner. Both delete only this device's copy: changes not yet synced are lost, and relays keep the data. With `createEvoluApp`, [`app.remove`](/docs/api-reference/common/local-first/Evolu/interfaces/EvoluApp#remove) deletes an AppOwner's data and removes it from this device's list, as the [full playground](/playgrounds/full/instant) does.

To learn more about Evolu, explore our [playgrounds](/docs/playgrounds) and [examples](/docs/examples).
