# Indexes

Are your queries taking too long to run? Measure their performance using the `logQueryExecutionTime` option:

Using the `Schema` from [Define schema](/docs/local-first#define-schema):

```ts
import { createQueryBuilder } from "@evolu/common";
// ---cut-start---
import {
  AppName,
  assertTrue,
  createConsole,
  createConsoleArrayOutput,
  createEvolu,
  id,
  NonEmptyTrimmedString100,
  testAppOwner,
  type ConsoleEntry,
} from "@evolu/common";
import { createEvoluDeps, createRun } from "@evolu/web";

const Schema = { todo: { id: id("Todo"), title: NonEmptyTrimmedString100 } };
// ---cut-end---

const createQuery = createQueryBuilder(Schema);
const allTodos = createQuery(
  (db) => db.selectFrom("todo").orderBy("createdAt").selectAll(),
  {
    logQueryExecutionTime: true,
    // logExplainQueryPlan: false,
  },
);
// ---cut-start---

const entries: Array<ConsoleEntry> = [];
const run = createRun(
  createEvoluDeps({
    console: createConsole({ output: createConsoleArrayOutput(entries) }),
  }),
);
const evolu = await run.ok(
  createEvolu(Schema, {
    appName: AppName.orThrow("IndexesLogQueryExecutionTime"),
    appOwner: testAppOwner,
  }),
);
await evolu.loadQuery(allTodos);
assertTrue(entries.some(({ args }) => args[0] === "[logQueryExecutionTime]"));
// ---cut-end---
```

<Note>
  While indexes may not be needed during early development, they are crucial for
  production performance. Use the `logQueryExecutionTime` and
  `logExplainQueryPlan` options in `createQuery` to measure and analyze
  performance.
</Note>

Without an index on the columns a query filters, joins, or sorts by, SQLite reads the whole table, and a nested query, such as one built with `evoluJsonArrayFrom`, reads it again for each parent row. Measured through Evolu with native SQLite on a MacBook Air, a page of 50 todos sorted by `createdAt` from a table of 100,000 took about 5 milliseconds with an index and 15 without one, while nesting those todos into 100 projects took about 90 milliseconds with an index on `projectId` and 700 without one. Browsers and slower devices take longer.

Evolu indexes the `id` column of every table itself, so a query that finds or joins rows by ID needs no index of its own.

For deeper insights into how SQLite indexes work under the hood, read [this in-depth guide](https://medium.com/@JasonWyatt/squeezing-performance-from-sqlite-indexes-indexes-c4e175f3c346).

<Heading level={2} id="usage">
  Usage
</Heading>

Using the schema, shared `run`, and `appOwner` from [Create Evolu](/docs/local-first#create-evolu):

```ts
import { AppName, createEvolu } from "@evolu/common";
// ---cut-start---
import {
  assertTrue,
  createConsole,
  createConsoleArrayOutput,
  createQueryBuilder,
  id,
  NonEmptyTrimmedString100,
  testAppOwner,
  type ConsoleEntry,
} from "@evolu/common";
import { createEvoluDeps, createRun } from "@evolu/web";

const Schema = { todo: { id: id("Todo"), title: NonEmptyTrimmedString100 } };
const entries: Array<ConsoleEntry> = [];
const run = createRun(
  createEvoluDeps({
    console: createConsole({ output: createConsoleArrayOutput(entries) }),
  }),
);
const appOwner = testAppOwner;
// ---cut-end---

const evolu = await run.ok(
  createEvolu(Schema, {
    appName: AppName.orThrow("MyApp"),
    indexes: (create) => [
      create("todoCreatedAt").on("todo").column("createdAt"),
    ],
    appOwner,
  }),
);
// ---cut-start---

const createQuery = createQueryBuilder(Schema);
const todosByCreatedAt = createQuery(
  (db) => db.selectFrom("todo").select("id").orderBy("createdAt"),
  { logExplainQueryPlan: true },
);
await evolu.loadQuery(todosByCreatedAt);
assertTrue(
  entries.some(({ args }) =>
    args.some(
      (arg) => typeof arg === "string" && arg.includes("todoCreatedAt"),
    ),
  ),
);
// ---cut-end---
```

Evolu handles this automatically—it will create any new indexes you define and drop those no longer present in the `indexes` array.

Unique indexes are rejected because concurrent offline writes can violate uniqueness during synchronization. See [Uniqueness](/docs/schema#uniqueness) for how to handle duplicate business values. Index names starting with `evolu_` are reserved for Evolu.

<Heading level={2} id="recommendations">
  Recommendations
</Heading>

SQLite offers a powerful [CLI tool](https://sqlite.org/cli.html#index_recommendations_sqlite_expert_) for index recommendations.

To use it:

1. Download the "Precompiled Binaries" [here](https://www.sqlite.org/download.html).
2. Open your database or create a new one.
3. Run `.expert` and paste in the SQL of the query you're analyzing.

You can get the query SQL using the `logQueryExecutionTime` option in `createQuery`, which logs the full SQL statement for easy copy-paste.
